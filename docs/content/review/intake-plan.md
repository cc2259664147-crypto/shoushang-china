## 1. 候选号与未来内容ID

候选号只用于审阅追踪，不直接作为正式数据库ID。隔离录入时建立一份受控映射清单，至少包含：候选号、拟定稳定内容ID、实体类型、初始修订号、对应媒体候选、来源编号、署名版本、审核决定版本和录入批次。

- 工艺：复用总控确认的正式剪纸工艺ID；不得把开发工艺ID直接转正。
- 模板：建议由总控分配如 `template-papercut-...` 的正式稳定ID，并保存与 T-C01—03 的映射。
- 媒体：每张上传后使用后台生成的 mediaId，映射到 manifest 的文件哈希；不得预造 mediaId。
- 展品：E-R01—10、E-R13、E-R14 在负责人采用后分别映射到新 Exhibit ID。
- 故事：S-C01—03 在人物稿和封面批准后映射到新 Story ID。

映射表必须留在受控录入证据中；候选号继续保留用于追溯，但不得对外宣称是数据库正式ID。

## 2. 依赖顺序

1. 冻结负责人批准的文案、来源、许可和署名版本。
2. 在全新隔离目录初始化数据库、媒体根和备份根，创建隔离责任人账号。
3. 确认正式工艺记录存在且可引用。
4. 由总控安排三套模板的受控接入与版本快照；模板必须先于引用它的故事发布。
5. 按 manifest 选择原件或上传件，核对哈希后通过后台上传媒体，填写许可台账并完成媒体审核。
6. 录入十二件展品草稿，关联已批准的媒体和工艺；当前故事、模板关联默认留空，除非负责人另有逐条证据和决定。
7. 录入三篇故事草稿，关联非肖像编辑封面、工艺及已启用模板；`exhibitIds` 当前为空。
8. 编辑提交审核，审核人与编辑账号分离；逐条检查公开投影、来源、署名及关联。
9. 先在隔离前台发布验证，完成撤回和恢复演练；正式发布须另行批准。

## 3. 现有后台可完成的操作

M13 后台现有能力可用于：账号鉴权、展品和故事草稿保存、媒体上传与许可记录、提交审核、审核决定、发布、下架、媒体撤权、账号停用、审计查询及数据库/媒体联合备份。所有动作走现有后台HTTP和受控命令，不直接连接 SQLite，不调用通用SQL执行器。

后台当前只编辑展品和故事，不能创建正式工艺或模板。工艺和模板接入需要总控安排受控初始化或后续明确的管理能力；不得把 `tests/m14` 隔离 runner、开发模板ID或测试许可字段接入生产启动。

## 4. 原件、上传件与证据对应

- `assets/m14-3c/manifest.json` 是候选文件、哈希和派生关系索引，不是后台许可证明本身。
- 后台上传前重新计算原件和上传件 SHA-256；记录上传返回的 mediaId、实际保存哈希、尺寸和格式。
- E-R01 使用 `spring-upload.webp`，必须同时关联 `spring-original.png`，说明有损 WebP 派生。
- 三张故事封面使用 `story-editorial-s0*-upload.png`，同时保留源 SVG，并写明“项目数字示意／编辑封面，非人物作品”。
- 其余当前展品候选的 `uploadFile` 与 `file` 相同，不产生新的编辑修改；若录入前裁切、压缩、调色或重编码，必须生成新文件、哈希、派生记录、修改说明和重新审核，不覆盖原件。
- 许可页面、来源摘记和内部核验材料分别受控保存；公开 DTO 只出现允许公开的来源、署名和许可字段，不公开 proofRef、内部路径或凭证正文。

## 5. 账号、角色与真实责任人

隔离执行至少需要：一名编辑录入草稿、一名不同的审核人审查事实与许可、一名发布责任人批准发布操作。可以由组织实际人员兼任允许的角色，但审核不得由自动化伪造，也不得以AI自查代替签字。账号由现有维护CLI在服务停止状态创建，随机密码不进入日志、截图或URL；完成后停用隔离账号。

负责人需事先确认：十二件编辑集合、三篇故事、三套模板用途、所有媒体使用条件、署名展示方式、BnF用途性质、E-R09/E-R10残余风险处理，以及谁承担编辑、审核和发布责任。

## 6. 全新隔离环境

为录入验证创建一个新的项目外临时根目录，内部至少分离：

```text
m14-content-intake-<random>/
  content.sqlite
  media/
  backups/
  logs/
  mapping/
```

`CONTENT_DATABASE_PATH`、`ADMIN_MEDIA_ROOT`、`ADMIN_BACKUP_ROOT` 均指向该隔离根内互不包含的绝对路径；后台只监听 127.0.0.1，使用明确的 loopback-http 模式和独立浏览器上下文。不得复用正常开发库、正式库、普通浏览器 profile 或 M14-3B 教学 runner 的数据库。媒体目录不作为静态目录暴露。

## 7. 验证和失败回退

每个阶段保存批次清单和公开读取快照：

1. 上传后验证真实解码、尺寸、缩略图、许可字段、私有凭证不可公开访问。
2. 草稿阶段验证公开前台仍不可见；字段失败时保留输入并修正，不跳过校验。
3. 审核阶段核对来源链接、图片、alt、署名、修改说明和关联；过期审核必须重新提交。
4. 发布后从正常公开HTTP核对列表、详情、图片和 no-store；逐项比较批准版本。
5. 对一件隔离候选演练下架和媒体撤权，确认后续公开读取立即失效；再通过新修订恢复，不修改历史修订。
6. 执行数据库及媒体联合备份，恢复到第二个全新目录，验证媒体哈希、公开状态、账号停用和会话撤销。

任一阶段失败都停止后续发布：未发布草稿保留供修正；已发布内容通过后台下架，不直接删表；媒体疑点通过撤权阻断；数据库/媒体回退使用已验证的联合备份恢复到新目录。原始素材、manifest、批准版本和审计记录均保留。
