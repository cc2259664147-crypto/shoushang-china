# V1.0 初版候选交付说明

说明日期：2026-10-23。当前交付工具从工作区允许清单收集运行成果，包含未提交但有效的成果，不以 Git 跟踪状态决定是否入包。旧批次一律保留；新修改必须产生新批次、清单与哈希。技术验证结论及最终包路径以交付工作区 `docs/handoffs/V1-initial-release.md` 与批次目录的 `version.json`、`package-hashes.json` 为准（交接文档含本机路径与批次细节，不随压缩包分发）；本文不替代实测报告或比赛批准。

## 包的范围

完整版与匿名版均包含前后端、共享包、冻结依赖清单、配置示例、显式 V1 内容初始化工具、`v1-initial-2026-10-22` 内容集及其中正式 `records.json`、15 项现用媒体、字体与许可、来源及第三方署名。独立初始化后应得到 3 套模板、12 件独立展品和 3 篇完整故事。初始化使用数据库公开封装和正常后台 HTTP，不依赖 `tests/m14`、旧临时数据库或原工作区文件。

两包都不包含 `.git`、`node_modules`、构建产物、缓存、实际或测试数据库、私有媒体库、备份、日志、浏览器资料、账号、会话、令牌、密码、私有授权凭证或 M14 完整证据。原始历史 E-R06、E-R15、E-R16素材已退出当前集且不入新候选包；其历史在原仓库保留。新 E-R17、E-R18、E-R19为独立记录，不能将裁切或同一作品多照重复计为展品。

完整版可含额外的内部编辑资料；匿名版只保留运行、初始化、来源和法定署名所需材料。匿名处理仅在暂存副本进行，移除选手身份、工作站绝对路径和私有仓库标识。两版均不猜填真实队伍姓名、学号或联系方式，也不删除第三方作者、机构、字体版权或许可。

每个包内包含：

- `DELIVERY-VERSION.json`：批次、包类型和候选状态；
- `DELIVERY-MANIFEST.json`：除清单本身外各文件大小与 SHA-256；
- 根 `README.md`：该包实际支持的安装、初始化、构建、启动与检查命令；
- 来源台账、第三方署名和字体许可。

外层候选包按已提供手册的结构要求容纳完整、匿名两个子压缩包。真实命名字段未补齐时，外层包仍须明确标为候选，不可把占位名称当正式提交。压缩包 SHA-256 与逐文件清单存放在新批次目录；包和报告必须属于同一批次。

## 从全新解压目录复现

使用 Node `>=24.19.0 <25` 与 pnpm `11.25.0`，在新解压目录执行根 README 的安装、类型检查、构建、`pnpm test:delivery`、`pnpm content:initialize -- --root <包外绝对空目录>` 和启动步骤。不要引用原仓库 `node_modules`、数据库、测试 runner 或临时文件。

`test:delivery` 是包内必要集成检查，真实验证初始化数量、重复执行及已有库保护，并核对临时账号/会话清理。精简包不含开发仓库全部单元和浏览器测试，所以 `pnpm test` 及历史文档中的 Playwright/M14 命令仅限完整开发仓库，不能作为精简包的必需步骤，也不使用空测试冒充通过。

显式初始化成功才会写完成回执；失败以非零状态退出并保留错误现场。同版本完成目录重复执行不会灌入第二份内容；已有库或非空目录默认拒绝。初始化用的随机临时账号在结束时停用，没有默认登录凭据。普通启动不静默初始化。

正常公开启动也需设置 `CONTENT_DATABASE_PATH` 与 `ADMIN_MEDIA_ROOT` 指向同一个包外私有根目录中的数据库和媒体。后台默认关闭，普通模式不设置后台 Origin、安全模式或备份配置。确需后台维护时按根 README 完整配置并显式创建个人维护账号。数据库、媒体、备份和凭证不得映射为静态目录。
