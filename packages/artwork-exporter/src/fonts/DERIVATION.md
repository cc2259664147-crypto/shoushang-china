# Shoushang Card Sans (M14-2B)

These local WOFF shards derive exclusively from the preserved `NotoSansSC-Regular.otf`, version 2.002. Original provenance is in `SOURCE.md`; original binary and `OFL.txt` are retained unchanged. Copyright Adobe 2014–2020 remains in the binaries. All derivatives remain under SIL OFL 1.1; the upstream reserved font name is **Source**. Derivative family/full/PostScript/CFF names use **Shoushang Card Sans / ShoushangCardSans**, avoiding the reserved name. They are bundled with this application, not sold separately. PNG artwork is not subject to the font license.

Rebuild from the repository root, without network or dependency installation:

```powershell
C:\python\python.exe tests/m14/build-card-font.py
```

The installed Python 3.13.10, FontTools 4.62.1 and built-in zlib produce lossless WOFF (not WOFF2). `generation.json` records exact tool versions, input/license SHA256, every output SHA256/size and Unicode codepoints. The script keeps the original timestamp, copies copyright/license name records, changes derivative naming, and verifies every output cmap, original advance width and decomposed glyph outline against the original font. Rebuilding is deterministic with these tool versions. No runtime external font service is used.

An independent second in-memory rebuild of `base,u0054,u0310` was byte-for-byte identical (`font-rebuild-check.log` for the initial version and `font-rebuild-uvs-check.log` after preserving all variation mappings, in M14-2B evidence). Reproduce that check without overwriting files using `C:\python\python.exe tests/m14/build-card-font.py --verify-shards base,u0054,u0310`. A second full rebuild of all 208 files was not run; the normal command rebuilds all files and performs exhaustive cmap/advance/outline/variation checks.

The union is the **entire original 30,892-codepoint nominal cmap**, not a test-title subset. All **25 original cmap format14 variation sequences** are also retained. Shards are disjoint: one base holds all original codepoints below U+0400 (keeping Latin and combining accents together), every fixed card label/date/ellipsis character, and every variation-sequence base. U+FE00/U+FE01 are included in that face's Unicode range, keeping every supported base/selector cluster together. Every other original codepoint belongs to its Unicode 256-codepoint page. Literal local asset URLs use `?no-inline` so small fonts are not silently embedded or transferred before export. Metadata itself contains no glyph bytes. Unsupported selector/base pairs are disclosed, rather than claiming that selectors have standalone glyphs.

The generation log records an incremental rebuild after the format14 audit: `--incremental` reuses only hash-checked shards with unchanged nominal codepoints and no variation bases; changed shards are regenerated. Every shard, including reused shards, is decoded and its cmap/metrics/outlines/variation mappings verified against the source. The normal full command remains available and rebuilds everything without reuse.

After the button event, the exporter requests the base and every page required by the actual snapshot name, including characters beyond displayed ellipsis. Each face is loaded with its exact Unicode range and checked for `loaded` status before drawing. Failed/timed-out requests return `RESOURCE_UNAVAILABLE`; retry requests missing faces again. A superseded late face cannot register. Successful faces can be reused offline; a new title requiring an unloaded shard while offline fails explicitly and can be retried online. Promise/face retention is bounded by the finite manifest, scoped to the current document and cleared by page reload. Successful partial loads after another shard fails are safe to reuse.

Coverage limits are inherited from the original font. Characters absent from its cmap, including many emoji, ZWJ sequences and rare CJK characters, may use device fallback and are **not** claimed as bundled-font coverage or successful built-in glyph loading. `unsupportedCardCharacters` identifies that boundary; the workshop explicitly asks the user to inspect preview when such a name is exported. Existing emoji export/layout behavior is retained, with no guarantee of emoji shape or absence of missing-glyph boxes across devices. Supported glyph outline/advance equality is exhaustively checked by the generator; browser tests separately compare selected Latin/combining/CJK/page-boundary pixel output to the original font. This does not certify every complex-script shaping sequence or true-device rasterization.
